## Проверки критериев A–F

| Критерий спецификации | Проверка и доказательство |
|---|---|
| A: `init` нового и существующего проекта, сборка | `TestEndToEnd`: создание, закрепление окружения, сборка; исходники и CMakeLists существующего проекта сохраняются. `offline_smoke.sh` использует настоящие пакеты RP2040. |
| A: логи и редактор | `pack` сохраняет полный лог проверочной сборки; `build` выводит лог в терминал. Smoke-тест проверяет непустой `compile_commands.json`, пути нового хранилища и отсутствие старых; при доступности clangd выполняет `--check` с ARM `--query-driver`. В CI clangd обязателен. |
| B: офлайн-проверка и отказ при обязательной загрузке | `TestEndToEnd` проверяет сетевой probe и отказ `pack` при обязательной сетевой зависимости. CI требует доступности network namespaces. Реальный smoke-тест восстанавливает и собирает внутри отдельного namespace без сети. |
| B: состав слепка и исходный проект | `TestFiles`, `TestFilesRejectsSymlink`, `TestEndToEnd`: секреты, исключения, каталог сборки, ссылки. `TestSignalDuringPack`: исходники сохраняются; незавершённый слепок не публикуется. |
| B: хостовые зависимости | `TestLeaks`, `TestNinjaLeaks`, `TestEndToEnd`: пути системных инструментов в CMake cache и правилах Ninja вызывают отказ `pack`. |
| C: чистый получатель без интернета | Пользователь подтвердил CachyOS → чистый CachyOS Live с отключённой сетью. `offline_smoke.sh` использует второе пустое хранилище и принудительно отключает сеть получателя; сравнивает UF2. |
| D: повреждение, версия, платформа и конфликты | Тесты `internal/snapshot`, `internal/manifest`, `internal/pkgtar`, `internal/safepath`: контрольные суммы, лишние/повторные/отсутствующие записи, traversal, опасные ссылки, новая версия формата, чужая платформа и существующий каталог назначения. |
| E: сборка без платы | Все автоматические сборки и реальный smoke-тест выполняются без платы. |
| F: безопасная очистка | `TestGC`, `TestRegistry`, `TestEndToEnd`, `TestConcurrentInitAndGC`: используемые общие пакеты сохраняются, исходники не удаляются, `gc` показывает план и ждёт активные команды. |

## Проверки отказов и параллельной работы

- `TestDiskFullFilesystem`: настоящий tmpfs 1 МиБ, ENOSPC при упаковке,
  восстановлении, установке пакета, записи lock и HTTP-загрузке.
  Старый lock сохранён, частичные результаты не публикуются.
- `TestSignalDuringPack`: SIGINT/SIGTERM, очистка рабочей копии и код
  130; SIGKILL, очистка старого остатка через `gc` и повторный `pack`.
- `TestKilledInstallRecovery`, `TestKilledUnpackRecovery`: SIGKILL,
  отсутствие готового имени и успешная повторная операция.
- `TestCancelStalledDownload`, `TestCancellationDuringArchiveRead`,
  `TestCancellationDuringArchiveWrite`: отмена потоковых операций.
- `TestCancelStopsDescendants`: отмена завершает группу процессов Linux.
- `TestConcurrentInitAndGC`: два процесса CLI, одна общая загрузка,
  две записи реестра; `gc` не удаляет даже состаренные данные живого `init`.
- `TestConcurrentRegistration`, `TestSharedExclusiveAndSIGKILL`:
  отсутствие потерянных записей и освобождение блокировки после аварии.

Исходники проверок: [CLI](../cmd/slepok/), [snapshot](../internal/snapshot/),
[runner](../internal/runner/), [store](../internal/store/),
[filelock](../internal/filelock/), [реальный smoke-тест](../scripts/offline_smoke.sh).

## Границы гарантий

- Без network namespaces программа предупреждает и допускает сборку с
  сетью; офлайн-свойство в этом случае не доказано. CI не допускает такой
  fallback при приёмке.
- Проверка путей ищет известные системные префиксы в cache и правилах
  Ninja. Она не интерпретирует произвольные shell/Python-скрипты и не
  заменяет проверку восстановления в чистом окружении.
- SIGKILL не позволяет выполнить очистку. `gc` убирает старые остатки
  внутри хранилища; соседние временные файлы/каталоги проекта требуют
  ручного удаления. Тесты SIGKILL не моделируют потерю питания.
- Linux-инструменты требуют совместимых системных библиотек; слепок
  содержит toolchain, но не отдельную операционную систему.
