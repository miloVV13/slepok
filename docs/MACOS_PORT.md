# macOS — продолжение этапа 5

После ручной приёмки Windows → Windows и Windows → Linux начата
подготовка macOS. Платформы: `macos-arm64` (Apple Silicon) и
`macos-x64` (Intel). Готовая поддержка RP2040 на macOS пока не заявлена.

## Основа

- Межпроцессные блокировки через `flock`, включая ожидание с отменой
  и освобождение блокировки при завершении процесса.
- Инструменты запускаются в отдельной группе процессов; отмена
  завершает группу, как на Linux.
- Хранилище по умолчанию: `~/Library/Application Support/slepok`.
  `SLEPOK_HOME` остаётся необязательным override; XDG_DATA_HOME на
  macOS не используется. Путь с пробелами учитывается автоматически.
- Unix-признаки исполнения и ссылки входят в прежний канонический tar;
  TTY-индикатор использует ioctl, как Linux-вариант.
- Сетевая изоляция Linux не переносится автоматически: macOS пока
  использует предупреждение об отсутствии изоляции.

Локально прошли Linux `go test -race ./...`, кросс-сборки CLI для
`darwin/arm64` и `darwin/amd64`, Darwin `go vet`. Добавлен `macos-core`
в GitHub Actions: нативные тесты основы, без заявления готовности
RP2040-профиля. Пакеты toolchain для macOS ещё не закреплены.

## Следующие шаги

1. Подтвердить основу нативными тестами на macOS; кросс-компиляция
   сама по себе не доказывает работоспособность.
2. Закрепить vendor checksum и package digest всех RP2040-компонентов
   для выбранных архитектур; проверить доступность нативных SDK tools.
3. Добавить host-настройки профиля и выбор `--platform`, сохранив
   существующие Linux/Windows digest и формат слепка.
4. Проверить Mach-O архитектуру, зависимости dylib, релокацию,
   quarantine/codesigning и работу на стандартной файловой системе
   без требования изменить настройки безопасности системы.
5. Нативный цикл `init → build → pack`, затем чистый получатель
   без сети: macOS → macOS и миграции с Linux/Windows. SHA256
   сравнивать для одинаковых исходников, lock и хостовой платформы.

Проверки shell, отмены, read-only деревьев, длинных путей и регистра
необходимо включить в нативную приёмку. Unix-права сами по себе не
устраняют различия стандартной macOS-файловой системы и Linux.
